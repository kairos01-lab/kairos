# Manifesto (opinião)

> Este texto é opinião do autor, não resultado científico. Ele não substitui o
> protocolo, a auditoria ou os limites descritos em `docs/TCI.md` e
> `docs/RESULTS.md`.

## Uma pessoa, uma bancada de LLMs e a teimosia de ligar as caixinhas

Enquanto bilhões são gastos em ilhas de pesquisa — um laboratório faz o modelo,
outro faz a avaliação, outro faz a segurança, outro faz a filosofia, outro faz o
produto — este projeto nasceu de **uma pessoa em simbiose com uma bancada de
LLMs**, tentando manter tudo no mesmo lugar: estado, política, memória, prompt,
segurança, experimento e auditoria.

Não é uma crítica à ciência. É uma crítica à **fragmentação**. A ciência séria
precisa de especialistas; o problema é quando a especialização vira uma caixinha
fechada e ninguém consegue ligar os pontos.

Investir bilhões para estudar uma caixinha por anos e chamar isso de “estado da
arte” pode otimizar o conhecido e ignorar o que está **entre** as caixas. O
próximo salto não é uma caixinha maior. É a **conexão** entre as caixinhas.

## O que este projeto tenta fazer

- Manter o estado interno explícito, não escondido no prompt.
- Separar política de LLM: o modelo não decide o nível de estresse.
- Tratar memória, segurança e auditoria como partes do sistema, não como
  plugins de última hora.
- Publicar o erro antes de publicar o hype.
- Dizer “não sei” e “não foi executado” quando for verdade.

## O que não queremos

- Vender consciência fake.
- Chamar TE de Φ_MIP sem prova.
- Transformar um resultado C em evidência A.
- Publicar um piloto não executado como se fosse resultado.
- Pedir validação automática porque o código é aberto.

## O que queremos

- Revisão adversarial.
- Parcerias de pesquisa com quem aguenta a crítica.
- Investimento que entenda que infraestrutura e método também são produto.
- Pessoas que queiram ligar as caixinhas, não apenas defendedê-las.

## Nexialismo

O criador se define como **nexialista**: alguém que integra disciplinas para
resolver o que uma área sozinha não resolve. Não é um título; é uma postura.

Se você também é assim, o repositório está aberto. Se você discorda, melhor
ainda: abra uma issue e mostre onde o argumento quebra.

**Kairós** é o nome do projeto. O processo é humano-máquina. A responsabilidade
é humana. O erro é documentado. O experimento continua bloqueado.
